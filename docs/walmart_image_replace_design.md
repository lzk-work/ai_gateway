# Walmart 副图替换设计方案

> 更新日期：2026-09-18。本文是当前需求与实现约定，替代先前主图生成及 OSS 版本控制阻断规则。技术基线为 walmart_image_prompt 和共享引擎。历史交接报告不覆盖本文需求。

## 1. 目标与范围

每个店铺下的结果 SKU 保留原主图，最终至少有 4 张新副图。

- 原主图链接必填，原样沿用，不区分新旧、文件名或历史 SKU；本次不生成、不上传、不替换、不归档主图。
- 已有新副图全部保留，超过 4 张不截断，不足 4 张才补生成。旧副图不进入最终图集。
- 来源 SKU 决定新增图片目录和命名；结果 SKU 是使用这些图片的沃尔玛商品，两者不同。
- 已有图片允许跨目录、跨文件名 SKU 复用，不改名、不搬迁。
- 同来源 SKU 对应多个结果 SKU 时逐行独立处理，允许共用已有图，不合并新生成任务。
- 模型参考仅使用输入中的沃尔玛参考主副图 URL，已有 OSS 图用于副图分类、计数、复用和目录推导。
- 输出最新使用、新生成、待归档三份图集。待归档只列输入中的旧 OSS 副图，不扫描目录，不移动或删除对象。
- 本项目仅准备图片和结果；线上图片更新由 E:/WorkSpace/walmart_api 项目承担。本项目不维护Walmart鉴权、店铺ID、Feed或线上状态。

## 2. Excel 输入与校验

每行一个店铺下的结果 SKU。SKU、店铺和 GTIN 应在 Excel 中以文本填写，避免前导零丢失；五点写在一个单元格内，可换行。

| 表头 | 要求 | 用途 |
| --- | --- | --- |
| 来源SKU | 必填 | 新图片命名和目录 |
| 结果SKU | 必填 | 平台商品归属 |
| 店铺 | 必填 | 与结果 SKU 共同标识商品 |
| 标题 | 需补副图时必填 | 提示词素材 |
| 五点 | 需补副图时必填 | 提示词素材 |
| 参考主图链接 | 需补副图时必填 | 沃尔玛参考素材，不是待替换主图 |
| 参考副图链接1、2…… | 可空，动态列数 | 沃尔玛参考素材，一列一张 |
| 已有主图链接 | 必填，有效 HTTP/HTTPS 图片对象 URL | 保留原 URL，支持 OSS 或沃尔玛链接 |
| 已有副图链接1、2…… | 可空，动态列数 | 目标 OSS 中已有副图，一列一张 |
| GTIN | 可选，已有值原样输出 | API项目提交前核验或查询补齐 |
| 商品类型 | 可选，已有值原样输出 | API项目product_type，缺失由API项目查询补齐 |

副图按表头数字后缀排序，忽略空单元格。已达标行不要求文案或参考链接齐全。URL 校验不等于远程图片可访问性验证。

- `(store, result_sku)` 在输入中必须唯一；重复行阻断，不生成两套图片。
- record_id 由店铺、结果 SKU 稳定派生，行号用于追溯；重复行用行号区分错误记录。
- 保存完整行输入指纹与行号。原批次允许末尾追加新行，或提高 max_records 纳入末尾新任务；已有行内容、行号和顺序必须不变。旧计划、名称、任务 ID 与检查点复用，只为新增行创建计划；修改、删除、插入或缩小范围报 input_changed，预演不写入追加计划。
- 已有副图按 bucket/object key 去重，忽略 URL 查询参数，保留首次出现的原 URL。不进行内容相似度去重。
- 副图新旧只看解码后的文件名：包含 new_sub 为新副图，兼容历史序号及时间戳命名。目录、域名和查询参数不参与新旧判断。
- 副图列出现 new_main 标记，或同时含主副图标记时阻断。原主图不按名称分类。
- 参考图校验为沃尔玛平台 URL；已有副图校验为当前目标 OSS bucket 的公网 URL。

## 3. OSS 目录、动态数量与名称

从已有 OSS URL 的对象父目录去掉最后一级历史 SKU，取得 bucket、endpoint 和路径基座，再拼接本次来源 SKU。符合目标 bucket 的 OSS 原主图也可参与目录推导；沃尔玛原主图及参考图不用于推导 OSS 目录。

```text
已有：images/walmart/HISTORY_A/new_sub1_HISTORY_A.png
来源SKU：SOURCE_B
新增目标：images/walmart/SOURCE_B/
```

保留完整前缀，不重复添加 images，不使用 prompt 的 develop 路径。需要生成时路径基座必须唯一；无法确定或多个基座时阻断，不猜测。无需生成的已达标图集允许跨路径基座复用，不要求能推导上传目录。

```text
need_main = 0
need_sub = max(0, 4 - 已有去重新副图数)
```

例如：原主图不变，已有 1 张新副图及 5 张旧副图，则补 3 张新副图，最终使用 4 张新副图；5 张旧副图列为待归档。已有 6 张新副图则全部保留，零生成。

```text
new_sub_{来源SKU}_{UTC毫秒时间戳}_{短随机标识}.png
```

名称创建时持久化，查询、下载、上传、重试沿用；明确失效后的重新生成仍使用原计划名称。来源 SKU 中不适合文件名的字符转换，原值另存。不按已有张数分配序号，文件名不依赖结果 SKU。

image_id 标识计划图片，record_id + image_id 标识商品使用关系。共享引擎使用 record_id 作为技术分组键；真实 OSS 目录及对象键使用来源 SKU，不能使用技术分组键。

## 4. 执行、上传与断点续跑

读取输入并保存计划 → 动态副图提示词 → 副图提交/分轮查询/下载 → 上传来源 SKU 原目录 → 保留原主图并合并新副图 → 完整性门控及三份输出。

### 提示词与图片任务

- 文本复用共享调用、网关重试、候选模型及并发接口；输出需有准确的 need_sub 条提示词，编号为 1..need_sub，内容非空。
- 成功提示词跳过；有效原始输出可恢复，避免恢复过程中重复调用。
- 临时文字调用失败留到后续轮次重试；明确源数据错误或参考图不可用单独保留失败状态。
- 图片使用 fixed 模式携带经校验的副图提示词，不依赖历史序号文件名解析。
- 整批绑定一个 provider，不进行单图平台降级。TUZI 使用分轮异步路径，其他平台按已有适配器能力运行。
- 取得 task_id 后立即保存；submitted/pending 复用原任务查询，不额外补提交。
- 下载 429 单图延后；普通下载故障保留 task_id；明确图片失效按重新生成上限处理。
- 无 task_id 的未知提交保存未知状态，重试可能再次计费；不承诺绝无重复计费。
- 已成功上传的图片不因本地文件丢失而重新生成。临时下载镜像补丁不参与本流程。
- 图片检查为签名及头尾轻量校验，不是内容 hash 一致性认证。

### 限速边界

文字请求由当前一次调用共享启动间隔，文字并发由总配置管理；允许的单请求重试使用阶段等待时间。遇到 429 尚未实现所有线程统一冷却，也不协调多个进程或平台其他用户配额。启动间隔不保证满足平台请求数或 token 限额。

图片提交、查询、下载和重试共享每次引擎 run 内的启动限速；响应可并发等待。文本、图片、OSS 使用各自设置，不承诺跨进程统一限速。

### OSS 上传

- 使用完整 object key，客户端 default_prefix 为空，保留本地文件检查。
- 依靠持久化唯一名称避开历史图片，直接上传；不查询对象存在性或 bucket 版本控制，不发送禁止覆盖请求头。
- 有成功 checkpoint 时核对计划对象键并跳过上传。
- 上传成功但记录保存前中断时，允许续跑重复上传同一对象键。此行为已由用户确认接受。
- OSS 接口失败仍记录为失败，不把异常当作上传成功。生成、上传记录相互独立。

### 批次与调度

- 布局版本为 3。兼容版本批次复用计划及 checkpoint；旧版本不自动迁移，不删除历史任务。
- 已有行改变或 provider 切换时使用新批次；末尾追加新行继续原批次；临时服务失败及下载延后继续原批次，不删除 checkpoint。
- max_records 按商品记录筛选，所有阶段使用同一入选范围，不按图片行数分别截断。
- 总入口支持 --dry-run、--once、--batch-name。无显式批次名时取配置输入文件名。
- --dry-run 只在内存分析，无外部接口、目录创建或业务写入。
- --once 单轮；周期运行按 scheduler 间隔续跑，图集全部完成后可自动停止。阻断或永久失败仍保留状态，需人工处理；不会自动清空任务。
- Ctrl+C 可在两轮等待时停止。一批次同时只运行一个进程。
- 三份报告可从记录重新派生，删除报告不应导致图片重提交。

## 5. 最终结果、错误与追踪

完成条件：原主图有效且唯一，至少 4 张新副图，无输入阻断；新生成副图须有匹配计划对象键的成功上传 URL。complete=true 只表示图集准备完成。

三份 XLSX/JSONL 保存全部输入记录，包括零生成及失败商品。主图单列，副图动态多列；保留GTIN及可选商品类型。

| 输出 | 内容与顺序 |
| --- | --- |
| 最新使用图片URL | 原主图 + 已有新副图 + 本批次上传成功的新副图；已有副图按输入序，新图按计划序追加 |
| 本批次新生成图片URL | 本批次累计上传成功的新副图；主图列空 |
| 待归档旧副图URL | 输入旧 OSS 副图，按输入序；主图列空，仅候选 |

输出包括来源 SKU、结果 SKU、店铺、可选 GTIN、URL、完整状态、错误、计划/生成/上传张数、归档状态。临时平台图片 URL 不作为最终 OSS URL。

提示词调用失败（含 403/429）及校验失败按 record_id 写入对应商品最终结果和三份报告。后续成功或有效提示词输出恢复后不再展示旧提示词错误；已完成图集不受历史提示词错误影响。未就绪图片仍保留当前生成或上传错误。

image_manifest 记录每张图片的身份、来源/结果 SKU、店铺、角色、来源、名称、目录、URL、对象键、任务、尝试及状态：

| 字段 | 含义 |
| --- | --- |
| input_column / input_order | 已有图原输入列名及数字后缀顺序；主图顺序为 1，去重保留首次出现列 |
| ordinal | 新图片计划顺序 |
| image_name | 计划名称；已有图片为解码后的文件名 |
| plan_created_at | 新计划创建时持久化的 UTC 时间，带时区 |
| generation_recorded_at | 共享图片引擎最新记录的 created_at |
| upload_recorded_at | 共享上传模块最新记录的 created_at |

后两项是记录时间，不是服务端实际完成时间，沿用原始本地时间格式。历史缺失时间留空，不从名称或文件修改时间推测。旧计划仅在输入指纹一致时从当前输入补列信息，派生不回写计划或修改名称/任务 ID。

prepared、not_ready、archive_candidate 表示准备状态，不表示线上已使用或已归档。待归档未完成商品也可列出；实际归档须检查其他商品使用关系，不按单行候选清单直接删除共用图片。

## 7. 两项目交接边界

当前项目输出05_result/image_set.jsonl和三份报告，仅表达图片准备状态；不输出平台提交状态、Feed ID或主副图更新开关，不保存Walmart店铺凭据。

交给API项目的文件是最新使用图片URL.xlsx，工作表图片结果，包含来源SKU、结果SKU、店铺、GTIN、可选商品类型、原主图URL、最终副图URL数字列、图集是否完整及失败原因。只有完整商品可进入API项目的导入路径。API项目使用自己的店铺配置把店铺名称映射到ID，以结果SKU定位当前店铺商品，核验或查询补齐GTIN及productType。

API项目导入时只提交最终完整副图列表，原主图仅用于审计，不放入更新载荷。真实更新、规范校验、提交恢复、Feed查询及线上逐商品状态全部由API项目负责。本项目不回调提交、不回写线上状态，不因API更新失败重建生图任务。旧replace_payload文件和历史任务数据保留，但不再作为新输出。

API对接说明见 E:/WorkSpace/walmart_api/docs/生图结果Excel对接.md。平台更新需要独立授权，本次对接只做离线验证。

## 9. 人工审核预览

独立入口09_replace_export_review.py，不接入自动生图或API提交。默认输出batches/<批次>/09_review/人工审核预览.xlsx。读取持久化计划并从当前成功上传记录派生最新图集，不写回计划、任务或API状态。

工作表人工审核预览：左侧为来源/结果SKU、店铺、GTIN、可选商品类型、标题、五点、图集完整状态、失败原因、审核结论/意见、预览加载问题。蓝色参考图区域展示沃尔玛参考主副图；绿色最新使用图区域展示保留原主图和最终副图。各商品占两行，上方缩略图、下方原图URL链接；各组主副图列明确命名，不把旧副图或未上传平台临时URL放入最新图。

所有商品保留，包括未完成行；未提供参考或未就绪图明确标注。审核结论默认待审核，可人工选择通过/退回并填写意见。审核导出不表示人工审核通过；完成人工审核后才交接最新使用图片URL.xlsx。审核预览不是API导入文件，本次不增加线上提交。

生成图优先使用本地已成功下载文件；参考及已有图按URL有限并发下载，压缩为最长边240px的JPEG。默认8路并发、超时30秒、单图上限20MB；相同URL仅在本次进程内复用，不写磁盘缓存。加载失败保留原URL和明确问题，不用其他图替代。--offline只读本地生成图，--dry-run不下载、不写文件。可配置缩略图尺寸100～400px、下载并发数和分卷上限，默认每卷最多1000个商品。超过4张的新副图仍全部展示。

再次导出默认拒绝覆盖已有审核文件以保护人工意见，可指定新输出路径；--overwrite仅在明确允许丢弃旧审核意见时使用。历史分卷不自动删除。
