# Text to Text 使用说明

本工具按 Excel 数据逐行生成完整提示词，每一行作为一个独立的 `user` 请求调用兔子文本 API，并将状态和结果保存在对应子任务自己的批次目录中。

## 1. 目录结构

```text
subtasks/text_to_text/
  run.py
  tasks/
    keyword_1688/
      task.json
      prompt.txt
      input/
        source.xlsx
      batches/
        <批次ID>/
          manifest.json
          state.sqlite3
          result.xlsx
          results.jsonl
          snapshots/
          raw_outputs/
```

不同子任务拥有各自独立的输入和批次目录，不会混用数据或处理状态。

## 2. 准备输入文件

将输入 Excel 放到当前任务的 `input` 目录。1688关键词任务的默认输入路径由 `task.json` 的 `input.default_path` 决定。

当前配置示例：

```text
subtasks/text_to_text/tasks/keyword_1688/input/1688_key_words.xlsx
```

程序不会把模型结果写回输入文件。运行时会在批次目录中保存输入快照，并单独生成 `result.xlsx`。

运行前建议关闭正在打开的输入 Excel，避免其他程序锁定文件。

## 3. 提示词占位符

提示词由用户维护。Excel 表头可以在提示词任意位置以占位符形式引用：

```text
{{ SKU }}
{{ Product Title }}
{{ Description }}
```

程序只替换用户已经写入提示词的占位符：

- 不自动添加字段；
- 不自动追加 Excel 内容；
- 不修改提示词；
- 不猜测不同表头之间的对应关系。

表头匹配忽略英文大小写和占位符两侧多余空格。如果占位符没有对应的 Excel 表头，dry-run 会报错并停止。

## 4. 查看可用任务

在项目根目录运行：

```powershell
cd E:\WorkSpace\ai_gateway
python .\subtasks\text_to_text\run.py --list-tasks
```

## 5. 试运行

```powershell
python .\subtasks\text_to_text\run.py --task keyword_1688 --dry-run
```

试运行会检查：

- 输入文件；
- 工作表；
- Excel 表头；
- 提示词占位符；
- 数据行数。

试运行不会调用兔子 API，不会产生模型费用，也不会创建正式批次目录。输出中显示的 `batch_id` 只是本次预检生成的临时编号，不能用于续跑。

## 6. 首次正式运行

完整运行：

```powershell
python .\subtasks\text_to_text\run.py --task keyword_1688
```

第一次正式运行会创建新批次，例如：

```text
keyword_1688_20261015_173020_424743
```

不传 `--latest` 或 `--batch-id` 时，每次正式运行都会创建一个新批次，并从当前输入文件重新开始。

## 7. 少量记录测试

只处理前3条待处理记录：

```powershell
python .\subtasks\text_to_text\run.py --task keyword_1688 --max-records 3
```

这会创建一个正式批次。后续需要继续同一个批次，必须使用 `--latest` 或明确指定 `--batch-id`。

## 8. 继续最近批次

```powershell
python .\subtasks\text_to_text\run.py --task keyword_1688 --latest
```

程序会读取该任务最近的批次状态：

- 已成功且请求内容未变化的记录跳过；
- 尚未处理的记录继续执行；
- 临时 API 失败的记录允许继续重试；
- 输入内容发生变化的记录重新处理。

继续最近批次并且每次只处理3条：

```powershell
python .\subtasks\text_to_text\run.py `
  --task keyword_1688 `
  --latest `
  --max-records 3
```

## 9. 继续指定批次

```powershell
python .\subtasks\text_to_text\run.py `
  --task keyword_1688 `
  --batch-id keyword_1688_20261015_173020_424743
```

指定批次比 `--latest` 更明确，适合同时保留多个测试批次时使用。

## 10. 修改输入数据后续跑

如果某行因数据问题失败：

1. 打开原始输入 Excel；
2. 修正对应行；
3. 保存并关闭 Excel；
4. 使用原来的 `batch_id` 续跑。

```powershell
python .\subtasks\text_to_text\run.py `
  --task keyword_1688 `
  --batch-id <原批次ID>
```

程序根据实际渲染后的完整请求计算输入指纹：

- 请求指纹没有变化并且已成功：跳过；
- 请求指纹发生变化：使用修改后的数据重新处理；
- 不需要删除 SQLite、清空结果表或将结果表作为输入。

## 11. 重复 SKU

通用框架不假设 SKU 唯一。默认内部记录键为 Excel 行号：

```text
row:2
row:3
row:4
```

因此 SKU 重复、为空或不存在都不会触发唯一性错误。如果用户主动在任务配置中设置 `record_id_template`，才会按用户指定的字段生成业务记录键并检查重复。

## 12. 中断与恢复

运行时可以按：

```text
Ctrl+C
```

停止程序。已完成的结果保存在 `state.sqlite3` 中。再次使用相同批次续跑即可：

```powershell
python .\subtasks\text_to_text\run.py --task keyword_1688 --latest
```

中断瞬间已经提交但尚未保存结果的请求，恢复时可能再次调用。

如果批次已经运行完成，需要重试该批次内的全部失败记录，使用：

```powershell
python .\subtasks\text_to_text\run.py --task keyword_1688 --latest --retry-failed
```

`--retry-failed` 会选择接口失败和结果校验失败的记录；请求指纹未变化的成功记录会被跳过。也可以将 `--latest` 替换为明确的 `--batch-id <批次ID>`。

## 13. 输出文件

每个正式批次位于：

```text
subtasks/text_to_text/tasks/<任务名>/batches/<批次ID>/
```

主要文件：

### `result.xlsx`

输入数据副本及模型结果。它是输出文件，不作为下一次输入。

### `state.sqlite3`

批次的权威状态库，记录每条数据的输入指纹、状态、尝试次数和解析结果。不要通过清空 `result.xlsx` 控制重跑。

### `results.jsonl`

便于程序或人工查看的结果导出，不是权威状态源。

### `manifest.json`

记录任务、版本、输入路径、工作表和输入文件哈希。

### `snapshots/`

保存每次正式执行时的输入文件快照，用于追溯。

### `raw_outputs/`

保存模型原始文本响应，便于定位解析或校验问题。

## 14. 多图片链接输入

`text_to_text` 可以选择性接收图片链接，无需建立单独项目。在新任务的 `task.json` 中，为 `input` 增加：

```json
"image_url_columns": ["主图链接", "附图链接"]
```

可以配置任意数量的图片列。每个单元格可以填写一个图片链接，也可以每行填写一个链接。重复链接会按首次出现顺序去重。

需要指定图片清晰度时，可在 `gateway` 中增加：

```json
"image_detail": "auto"
```

可选值为 `auto`、`low` 或 `high`。程序会把渲染后的完整文字提示词和所有图片链接放在同一个 `user` 消息中。未配置 `image_url_columns` 的任务继续使用原有纯文本请求格式。

图片链接及 `image_detail` 会进入请求指纹。图片内容发生变化后，该行会自动重新处理；其他未变化且已经成功的记录不会重跑。

如主图或其他图片列必须存在，可在 `input` 中增加：

```json
"required_image_url_columns": ["主图url"]
```

必填图片为空、空白或 `0` 时，该行会标记为 `input_invalid`，不会调用API。未列入必填配置的副图列允许缺失。

## 15. 常用命令汇总

```powershell
# 查看任务
python .\subtasks\text_to_text\run.py --list-tasks

# 预检，不调用API
python .\subtasks\text_to_text\run.py --task keyword_1688 --dry-run

# 创建新批次并正式运行
python .\subtasks\text_to_text\run.py --task keyword_1688

# 创建新批次，只处理3条
python .\subtasks\text_to_text\run.py --task keyword_1688 --max-records 3

# 继续最近批次
python .\subtasks\text_to_text\run.py --task keyword_1688 --latest

# 继续最近批次，只处理接下来的3条
python .\subtasks\text_to_text\run.py --task keyword_1688 --latest --max-records 3

# 继续指定批次
python .\subtasks\text_to_text\run.py --task keyword_1688 --batch-id <批次ID>
```

## 16. 安全说明

- API Key 从项目全局配置指定的环境变量读取，不写入任务目录。
- dry-run 不调用 API。
- 新批次和续跑必须明确区分。
- 输入文件只读，结果文件单独生成。
- 提示词受项目根目录 `AGENTS.md` 保护，未经用户明确批准不得修改。
